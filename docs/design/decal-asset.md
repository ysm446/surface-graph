# decal-asset — デカールアセットの設計

作成日時: 2026-11-25 16:21
更新日時: 2026-11-25 18:30

貼り物のアセット（メッシュデカール）を作る仕組みの設計。方針は [plan.md](../plan/plan.md) の
「デカールアセットの方針」、目的は [goals.md](../plan/goals.md) のゴール 4 / 5。

**実装済みなのは「実装の順番」の 1、2、4（メッシュの生成、アセットの組み立てと書き出し、エディタ）。**
エディタでプロジェクト（`.sgproj`）を開き、プロジェクトのグラフ・メッシュグラフ・マテリアルグラフを行き来して編集し、
3D ビューでアセットを見て、`.glb` を書き出せる。CLI の `asset` でも同じものが出る
（サンプルは `graphs/decal/repair_patch.sgproj`）。
まだ無いのは 3（タイルしない軸のサンプリングと検査、区画のマスクのノード）と 5（ビュー上でのパスの編集。
いまは頂点を数値で動かす）。**エディタのマウス操作は、人の手でまだ確かめていない**（スクリーンショットで表示だけを確かめた）。
プロジェクトファイルの形式は [project-format.md](../reference/project-format.md)。
決めきれていない点は最後の「未決定」にまとめた。

## 全体像

グラフを 3 種類に分ける。プロジェクトのグラフから、ノードをダブルクリックして中に入る。

```
プロジェクトのグラフ
  メッシュ ──▶ マテリアル ──▶ アセット出力（1 つ。入力の並び = 重ねる順）
   │              │
   │ ダブルクリック  │ ダブルクリック
   ▼              ▼
  メッシュグラフ   マテリアルグラフ（いまのアプリの画面）
  パス → 塗り / 線  ノイズ → … → Material Output
```

| グラフ | 作るもの | 評価 | 保存 |
| --- | --- | --- | --- |
| プロジェクト | アセット（マテリアルの付いたメッシュの重なり） | CPU | プロジェクトファイル |
| マテリアル | テクスチャ一式 | GPU（いまの評価エンジン） | プロジェクトに内包するか、`.sgraph` を外部参照する |
| メッシュ | パスとメッシュ | CPU | プロジェクトファイルに埋め込む |

- 1 プロジェクト 1 アセット。アセット出力はプロジェクトに 1 つだけ置く。
- `.sgraph` を単体で開く使い方（いまのアプリ）は、そのまま残す。CLI の `render` / `check` / `golden` も変えない。

## マテリアルの持ち方: 内包と外部参照

マテリアルグラフは、プロジェクトファイルに内包しても、外部の `.sgraph` を参照してもよい。
**どちらも中身は同じ形式**（[file-format.md](../reference/file-format.md) の JSON オブジェクト）で、
内包の場合はそのオブジェクトをプロジェクトファイルの中にそのまま持つ。

| | 内包 | 外部参照 |
| --- | --- | --- |
| 向く場面 | そのアセット専用のマテリアル。1 ファイルで完結させたい | 複数のプロジェクトで使い回すマテリアル。単体で CLI やテストに掛けたい |
| 保存 | プロジェクトの保存に含まれる | `.sgraph` を個別に保存する |
| アンドゥと未保存の状態 | プロジェクトのものに含まれる | プロジェクトのものに含まれる（下の注） |
| 画像ファイルの相対パス | プロジェクトファイルのあるフォルダから辿る | `.sgraph` のあるフォルダから辿る |

- プロジェクトの中で新しく作るマテリアルは、内包にする（ファイル名を聞かずに始められる）。
- 相互に変換できる。「外部ファイルへ書き出す」（内包 → 外部参照）と「プロジェクトに取り込む」（外部参照 → 内包の写し）。
  変換のとき、画像ファイルの相対パスを付け替える。
- 外部参照のパスは、プロジェクトファイルからの相対パスで保存する。
- 外部のファイルが見つからないときは、マテリアルノードをエラー（赤枠）にして、パスは保ったままにする。
- 外部の `.sgraph` がアプリの外で書き換えられたら、読み直す（Image ノードの画像と同じく、更新時刻を見る）。
  アプリの中で未保存の変更があるときは、読み直さずに知らせる。
- 複数のマテリアルノードが同じマテリアルを指してよい。評価は 1 回で済む。
- **アンドゥは、外部参照のマテリアルも含めてプロジェクト全体で 1 本にした**（当初の案は、外部参照はマテリアルごと）。
  外部参照のグラフも、読み込んだあとはプロジェクトのメモリの中に持っているので、スナップショット 1 つで戻せる。
  どの階層にいても Ctrl+Z が 1 つの履歴を辿るので、分かりやすい。保存は、プロジェクトと一緒に、変更のある
  `.sgraph` を書く。
- 外部の `.sgraph` がアプリの外で書き換えられたときの読み直しは、まだ無い（開き直すと反映される）。
- 内包と外部参照の変換（「内包にする」「外部へ保存...」）は、マテリアルノードのパラメータ欄にある。
  画像ファイルの相対パスの付け替えは、まだしていない。

## プロジェクトファイル

JSON、UTF-8。拡張子は `.sgproj`。実装済み（`src/project/Project.h`、`src/io/ProjectJson.cpp`）。
フィールドの細かい決まりは [project-format.md](../reference/project-format.md)。

```json
{
  "format": "surface-graph-project",
  "version": 1,
  "name": "repair_patch",
  "ground": 3,
  "materials": [
    {"id": 1, "name": "補修材", "graph": { "format": "surface-graph", "version": 1, "...": "..." }},
    {"id": 2, "name": "縁のシール", "path": "materials/sealant_edge.sgraph", "tileSize": 1.0},
    {"id": 3, "name": "アスファルト", "path": "materials/asphalt.sgraph", "tileSize": 2.0}
  ],
  "nodes": [
    {"id": 10, "type": "project.mesh", "pos": [0, 0], "graph": { "nodes": [], "links": [] }},
    {"id": 11, "type": "project.material", "pos": [300, -80], "material": 1},
    {"id": 12, "type": "project.material", "pos": [300, 80], "material": 2},
    {"id": 13, "type": "project.asset", "pos": [600, 0], "layers": [11, 12]}
  ],
  "links": [
    {"from": 10, "fromPin": "out:4", "to": 11, "toPin": "Mesh"},
    {"from": 10, "fromPin": "out:5", "to": 12, "toPin": "Mesh"}
  ]
}
```

| フィールド | 内容 |
| --- | --- |
| `materials[]` | マテリアルの表。`graph`（内包）か `path`（外部参照）のどちらかを持つ |
| `materials[].tileSize` | 1 タイルの実寸（メートル。短い辺）。塗りの UV の割り付けに使う |
| `ground` | 下地のマテリアルの ID。重ねて見るためだけに使い、書き出さない。無ければ単色の地面 |
| `nodes[].graph` | メッシュノードが持つメッシュグラフ |
| `nodes[].material` | マテリアルノードが指すマテリアルの ID |
| `nodes[].layers` | アセット出力に繋いだマテリアルノードの並び。先頭が一番下 |

読み込みの決まり（未知のノードを読み飛ばす、別名に書いてから差し替える）は `.sgraph` と同じ。

- 外部参照のマテリアルは、読み込むときに `.sgraph` を読んでメモリに持つ。保存では中身を書かない。
- プロジェクトのグラフは、`graph::Graph` とは別のモデル（`project::Project`）にした。メッシュノードの出力ピンと
  アセット出力の入力が、ノードごとに数が変わるため（`graph::NodeDef` はピンの数が固定）。
  マテリアルノードとアセット出力の繋がりは、リンクではなく `layers` の並びで持つ。

## プロジェクトのグラフ

| ノード | type | 入力 | 出力 | 内容 |
| --- | --- | --- | --- | --- |
| メッシュ | `project.mesh` | — | メッシュグラフのメッシュ出力ごとに 1 本 | メッシュグラフを 1 つ持つ |
| マテリアル | `project.material` | Mesh | Part | メッシュにマテリアルを適用する |
| アセット出力 | `project.asset` | Part を何本でも | — | 重ねる順に並べて 1 つのアセットにする |

- **メッシュノードの出力ピンは、中のメッシュ出力ノードから作る。** ピンは出力ノードの ID で識別し
  （`out:<ID>`）、表示にはその名前を使う。名前を変えてもリンクは切れない。
- **アセット出力の入力は、繋ぐたびに空きが 1 本増える。** 並びが重ねる順で、パラメータ欄で並べ替える。
- マテリアルノードのパラメータは、指すマテリアルと、1 タイルの実寸（`tileSize`）。
- マテリアルノードの入力に何も繋いでいなければ、アセットには何も足さない（マテリアルの編集だけに使える）。

## メッシュグラフ

グラフのモデル（ノード、リンク、パラメータ）、JSON、エディタはマテリアルグラフと共用する。
違うのは、ノードがシェーダを持たず CPU で評価されることと、ピンの型。

- グラフとノードの定義は種類（`graph::GraphKind`。Material / Mesh）を持つ。違う種類のノードは置けず、
  読み込みでは読み飛ばす。エディタのノードの追加メニューは、開いているグラフの種類のノードだけを出す。
- ノードの定義はマテリアルと同じレジストリ（`src/graph/NodeDefinitions.cpp`）に置く。
  処理は `src/mesh/MeshEvaluator.cpp` が `type` で選ぶ。
- Path と Mesh のピンは、同じ型同士でしか繋げない。

### 型

| 型 | 中身 |
| --- | --- |
| Path | 頂点の並び（XZ 平面、メートル）と、閉じているかどうか |
| Mesh | 頂点、インデックス、ピースの表 |

`src/mesh/MeshTypes.h`:

```cpp
struct Path {
    std::vector<Point2> points;  // Point2 は x が X、y が Z
    bool closed = false;
};

enum class PieceKind { Fill, Edge, OuterCorner, InnerCorner, StartCap, EndCap };

struct MeshVertex {
    Point2 position;  // XZ 平面、メートル
    Point2 uv;        // ピース内の UV（下の「UV の割り付け」）
    float alpha;      // 重なりのフェード用。普通は 1
};

struct Piece {
    PieceKind kind;
    uint32_t firstIndex, indexCount;
    float length;  // Edge だけ。帯の幅を 1 とした長さ
};

struct Mesh {
    std::vector<MeshVertex> vertices;
    std::vector<uint32_t> indices;  // ピースの順に並ぶ。辺が先、角と端が後
    std::vector<Piece> pieces;
};
```

- メッシュは平ら（高さを持たない）。高さのずらしが要るなら、書き出しのときに付ける。
- 三角形はすべて、X を右・Z を上に取ったときに反時計回り。UV も同じ向きで、反転しない。
- 閉じたパスは、反時計回りに揃えてから使う。進む向きの左が内側になる。

### ノード

| ノード | type | 入力 → 出力 | パラメータ |
| --- | --- | --- | --- |
| パス | `path.points` | → Path | 頂点（頂点列）、閉じる |
| 矩形 | `path.rect` | → Path | 幅、高さ |
| 塗り | `mesh.fill` | Path → Mesh | — |
| 線 | `mesh.stroke` | Path → Mesh | 幅、寄せ（内側 / 中央 / 外側）、角の処理（留め継ぎ / 丸め / 角ピース）、丸めの分割数、端のピース、重なりの長さ |
| メッシュ出力 | `mesh.output` | Mesh → | 名前 |

- **塗り**: 閉じたパスの内側を耳刈り法で三角形分割する。開いたパス、自己交差するパス、面積の無いパスは
  エラーにする。穴は扱わない。
- **線**: パスの両側（または片側）へ幅を取って帯にする。
  - **寄せ**: 閉じたパスでは囲まれた側が内側。開いたパスでは、進む向きの左が内側。
  - **留め継ぎ / 丸め**: 一続きの帯を 1 つの Edge にする（閉じたパスなら一周で 1 つ）。
    留め継ぎの断面は斜めになるので、角の手前と先に真っ直ぐな断面を入れ、模様の歪みを角のまわりだけに収める。
    丸めは、角の外側の縁を扇形に分割する。
  - **角ピース**: 90° の角を、帯の幅 × 幅の正方形のピースにする。左へ曲がる角（閉じたパスの出っ張った角）が
    OuterCorner、右へ曲がる角（凹んだ角）が InnerCorner。辺は角のピースの手前で区切り、角から角までが
    1 つの Edge になる。90° でない角は留め継ぎにする。
  - **端のピース**: 開いたパスの両端を、幅 × 幅の StartCap / EndCap にする。ピースはパスの端点の内側に置く
    （アセットの長さはパスの長さのまま）。
  - 辺が、角や端のピースが収まらないほど短ければエラーにする。
- **重なりの長さ**: 角と端のピースを、辺の方向へ延ばす長さ（帯の幅に対する比）。延ばした先の頂点の
  `alpha` を 0 にする。辺はそのまま通す（フェードさせるのは上側だけ）。
- **頂点列と文字列のパラメータ**: 新しいパラメータの型（`ParamType::Points` / `Text`）。頂点列は
  `ParamValue::points` に持ち、JSON では `[[x, z], ...]`。頂点はビュー上で動かす（下の「エディタ」）。
  文字列はメッシュ出力の名前に使う。
- 自動でパスを作るノード（シードからひび割れの経路を作る、など）はあとから足す。乱数は
  マテリアルグラフと同じく、シードからのステートレスなハッシュだけを使う。

### 評価

- CPU で評価する（`mesh::MeshEvaluator`）。ノードごとに内容のハッシュ（種類、パラメータ、上流のハッシュ）を作り、
  変わったノードだけを計算し直す。考え方はマテリアルの評価エンジンと同じ。
- 同じ入力からは、頂点とインデックスがビット単位で同じものが出る。
- 入力が繋がっていないノード、上流がエラーのノードはエラーになる（`NodeResult::error`）。
- メッシュ出力ノードの結果は `MeshEvaluator::Outputs` で、ノードの ID と名前つきで取れる。
- `src/mesh` に置き、`sg_graph` のライブラリに含める（GPU も UI も使わない）。単体テストはここだけをリンクする。

## UV の割り付け

**メッシュグラフはピース内の UV までを作り、テクスチャ上の UV はマテリアルを繋いだ時点で確定させる。**
マテリアルを差し替えても、メッシュグラフを直さずに済む。

| ピース | ピース内の UV | マテリアルを繋いだときの割り付け |
| --- | --- | --- |
| Fill | 位置そのもの（メートル） | `tileSize` で割る。テクセルが正方形になるよう、マップの縦横比を掛ける |
| Edge | u = 始点からの長さ（帯の幅を 1 とする）、v = 外側 0 〜 内側 1 | 辺の区画へ割り付ける。u は、ピースの端から端でタイルが整数回になるように伸縮させる |
| OuterCorner / InnerCorner / StartCap / EndCap | 0〜1 の正方形（下の「角と端の向き」） | それぞれの区画へそのまま割り付ける。0〜1 の外（重なりの部分）は区画の縁で止める |

- 実装は `mesh::AssignUvs`（`src/mesh/Asset.cpp`）。
- 帯のテクセルは、帯の幅と辺の区画の縦横比から決まる。`tileSize` は使わない。
  1 タイルの長さ（帯の幅を 1 とする）は、辺の区画のピクセルでの縦横比。ピースの長さをそれで割って丸めた回数
  （1 回以上）だけ、端から端で繰り返す。
- 閉じた帯で角ピースを使わない場合は、一周を 1 つの Edge として扱い、一周でタイルが整数回になるようにする。
- 反転はしない（接線の向きが変わるため）。
- 辺の区画は、U 方向に横幅いっぱい（x = 0、幅 = 1）であること。繰り返しを Wrap に任せるため。
- `tile` のマテリアルに線を繋いだときは、全体を辺の区画として使う。角や端のピースを持つメッシュを、
  その区画の無いマテリアル（`tile` / `band`）に繋ぐとエラーにする。
- 割り付けのとき、頂点をピースごとに分ける（ピースをまたいで共有しない）。
- **接線**もここで作る。テクスチャの u が増える向きで、割り付ける前のピース内の UV から求める
  （重なりの部分は割り付け後に u が潰れるので、割り付け後の UV からは求まらない）。

### 角と端の向き

角と端のピース内の UV は、**入ってくる辺の続き**として決める。入ってくる辺の向きが u、外側 0 〜 内側 1 が v。
メッシュ上での向き（どちらへ回っているか）は頂点の位置に入っているので、ピースは回転の情報を持たない。
テクスチャの区画には、次の向きで絵を描く（u が右、v が下）。

| ピース | 帯が入る辺 | 帯が出る辺 | 備考 |
| --- | --- | --- | --- |
| OuterCorner | 左 | 下 | 上と右が角の外側 |
| InnerCorner | 左 | 上 | 上の辺のうち、帯の外側は左寄り |
| StartCap | — | 右 | 左がパスの始点 |
| EndCap | 左 | — | 右がパスの終点 |

辺の上へ延ばした重なりの部分は、ピース内の UV が 0〜1 の外へはみ出す（左へ延ばせば u < 0）。
**割り付けでは、これを区画の縁で止める**（頂点の UV を 0〜1 に切り詰める）。重なりの部分には、区画の縁の
1 列が引き伸ばされて出る。頂点の `alpha` で透けていく部分なので、引き伸ばしは目立たない。
区画に重なりのぶんの絵を描いておく必要が無く、サンプラの設定にも頼らないので、どのエンジンでも同じに見える。

### マテリアルの区画

区画の配置は、マテリアルグラフの設定として持つ（`.sgraph` の `layout`。無ければ `tile`）。
省略できるフィールドを足すだけなので、既存のファイルはそのまま読める。
データ（`graph::MaterialLayout`、既定の配置を作る `graph::MakeLayout`、JSON）は実装済み。
エディタに設定の欄はまだ無いので、`.sgraph` に手で書く（[file-format.md](../reference/file-format.md)）。

| `layout` | タイル | 区画 |
| --- | --- | --- |
| `tile`（既定） | U も V も | 全体で 1 つ。塗りに使う |
| `band` | U だけ | 全体が辺。線に使う |
| `band-corners` | 辺の段の U だけ | 辺、外角、内角、始端、終端 |

`band-corners` の既定の配置。段の高さはマップの短い辺の 1/4 で、セルはピクセルで正方形:

```
┌───────────────────────────────┐
│ 辺（横幅いっぱい。U は Wrap）      │  1/4
├───────┬───────┬───────┬───────┤
│ 外角   │ 内角   │ 始端   │ 終端   │  1/4（正方形のセル）
└───────┴───────┴───────┴───────┘
  （残りは空き）
```

- 区画の矩形は、プリセットから決まる値を明示的に保存する（プリセットを後で変えても、保存済みのファイルが変わらない）。
- 区画の間には余白を取る。既定の配置では、各区画の内側へ段の高さの 1/32 を余白にする
  （1024 px のマップなら段が 256 px、余白が 8 px、区画の中身が 240 px）。保存する矩形は、余白を除いた中身。
  余白には、区画の縁の色を延ばして描いておくと、ミップマップでにじまない。
- **タイルしない軸のサンプリング**: `band` の V 方向は、Blur や Warp が反対側の端から回り込まないよう
  Clamp で読む。共通ヘッダのサンプリング関数（`sg_sample` など）が、グラフの設定を見て軸ごとに切り替える。
  ノードのシェーダは書き換えない。ノイズの周期は変えない。
- `band-corners` で区画ごとに絵を描き分けるには、区画のマスクと区画内の UV を出すノードが要る。
  角の区画で「輪郭からの距離」を出すノードも、断面の形を辺と揃えるのに役立つ。どちらもあとから足す。

## アセットの組み立て

プロジェクトのグラフを評価すると、アセットができる。

```cpp
struct AssetLayer {
    Mesh mesh;                     // UV は割り付け済み（テクスチャ上の UV）
    std::vector<Point2> tangents;  // 頂点ごとの接線（XZ 平面）。u が増える向き
    uint64_t materialId;
    std::string name;              // メッシュ出力の名前
};

struct Asset {
    std::string name;
    std::vector<AssetLayer> layers;  // 先頭が一番下
};
```

- 実装は `project::BuildAsset`（`src/project/Project.cpp`）。メッシュグラフを評価し、`layers` の順に、
  繋がったメッシュ出力へマテリアルの区画で UV を割り付ける。
- 組み立ては CPU だけで行う。3D ビュー、CLI、`.glb` の書き出しが同じ結果を使う。
- エラー（メッシュグラフのエラー、見つからないマテリアル、区画の不足）は、レイヤーごとに文にして返す。
  1 つでもあれば失敗にする。
- マテリアルのテクスチャは、マテリアルごとの評価エンジンが作る。編集していないマテリアルは、
  Material Output に繋がったマップだけを残して中間テクスチャを解放する。

## 3D ビュー

球や平面の表示（コンピュートシェーダーで交差させる）とは別に、アセットをラスタライズするパイプラインを持つ。
実装済み（`engine::AssetPreview`、`shaders/preview/asset_preview.hlsl`）。

- 背景 → 地面（下地のマテリアルを貼った平面。無ければ単色に 1 m の格子）→ レイヤー（下から）の順に描く。
- レイヤーはアルファブレンドで描く。不透明度は Opacity × 頂点の `alpha`。
  **深度は使わない**（当初の案は「見るが書き込まない」）。全部が同じ平面にあり、描く順だけで重なりが決まるため。
  視点は地面の下へ潜らせない。
- 同じレイヤーの中の三角形は、インデックスの順に描く（辺が先、角と端が後）。
- シェーディングは、球 / 平面の表示と同じ式（GGX、手続きの空）。共通のヘッダ（`shaders/preview/preview_shading.hlsli`）
  に切り出して、両方が使う。
- デカールでは Displacement による視差を使わない。
- 「表示設定 > UV チェッカー」で、マテリアルの代わりに区画の確認用の絵を貼る（CLI の `uv.png` と同じ色分け）。
- マテリアルグラフの中に入っているときは、形のプルダウンで、球 / 平面 / 角丸の立方体とアセットに貼った表示を切り替える。
  プロジェクトとメッシュの階層では、常にアセットを出す。
- 描く空間は、アセットの中心を原点に、長い辺の半分を 1 ぐらいに揃えたもの。カメラとライトのギズモは、
  球 / 平面の表示と同じ式のまま使える。
- 縦横 2 倍で描いて縮める（ポリゴンの縁と、遠くの地面のちらつきを和らげる）。ノードのテクスチャにミップマップが
  無いので、遠くの地面は背景へ溶かす。
- 重ね合わせは、トーンマップして表示色にしたあとで行う（リニアで重ねてからトーンマップするのが正しいが、
  中間の浮動小数のターゲットが要る。半透明の縁の色が少し違って見える程度なので、後回しにした）。
- マテリアルごとに評価エンジンを 1 つ持つ（`Application::MaterialEvaluator`）。開いていないマテリアルは
  Material Output までしか評価しない。**中間テクスチャの解放はまだしていない**（開いたことのあるマテリアルの
  ノードのテクスチャは残る）。

## エディタ

パスの編集を除いて実装済み（`src/app/ProjectPanel.cpp`）。操作の一覧は [design-guide.md](design-guide.md) の「プロジェクト」。

- **階層**: プロジェクトのグラフ、メッシュグラフ、マテリアルグラフの 3 つ。グラフのパネルを共用し、
  上端のパンくず（「repair_patch > sealant_edge」）で、いまの階層を示す。プロジェクトの名前を押すと戻る。
- **中に入る操作**: マテリアルノード、メッシュノードをダブルクリックすると中に入る
  （右クリックのメニューと、パラメータ欄の「編集」からも入れる）。
- **作業用の写し**: メッシュグラフとマテリアルグラフは、いつものグラフのパネルが編集する `m_graph` へ写して開き、
  毎フレーム、プロジェクトへ書き戻す。グラフのパネルのコード（ノードの追加、リンク、コピー、整列）はそのまま使える。
  プロジェクトのグラフは、ピンの数がノードごとに変わるので、専用の描画（`DrawProjectGraph`）を持つ。
- **ノードの追加メニュー**: いま開いているグラフの種類のノードだけを出す。プロジェクトのグラフでは、メッシュ、
  マテリアル（新規 / `.sgraph` を参照 / 表にあるもの）、アセット出力（1 つだけ）。
- **アンドゥ**: プロジェクト全体で 1 本（上の「マテリアルの持ち方」の注）。いまと同じスナップショット方式で、
  ノードの移動は対象にしない。戻した結果、いま開いているグラフが無くなったら、プロジェクトの階層へ戻る。
- **保存**: プロジェクトと、変更のある外部参照のマテリアルをまとめて書く。別の場所へ保存するときは、
  外部参照のパスを保存先からの相対パスに直す。
- **マテリアルの表**: マテリアルノードを足すと表に増える。どのマテリアルノードからも下地からも使われなくなった
  マテリアルは、ノードを消したときに表から外す（アンドゥで戻る）。
- **真上からのビュー**: プロジェクトとメッシュの階層では、2D ビューのパネルに、真上から見た絵
  （X が右、Z が下。ピースの色分け、三角形の辺、1 m の格子）を出す。プロジェクトではアセット全体、
  メッシュグラフでは表示中のノード（出力ピンのクリックで選ぶ）のパスかメッシュ。
- **メッシュグラフのノード**: サムネイルの代わりに、中身の数（頂点、三角形、ピース）を出す。エラーは赤い枠とツールチップ。
- **頂点列と文字列のパラメータ**: パラメータ欄に出る。頂点は 1 点につき X と Z の 2 行で、数値で動かす。
- **書き出し**: 「ファイル > アセットを書き出す...」（Ctrl+Shift+E）。CLI の `asset` と同じ `.glb` とテクスチャを書く
  （`engine::ExportAsset`）。
- **パスの編集**（まだ無い）: 真上からのビューで、頂点を追加、移動、削除する。グリッドへのスナップと、
  直角の拘束（隣の頂点と X か Z を揃える）を持つ。頂点の編集もアンドゥの対象にする。

UI は [design-guide.md](design-guide.md) に従う。

## 書き出し

`.glb`（glTF 2.0 のバイナリ）とテクスチャ一式を書く。実装済み（`src/mesh/GlbWriter.cpp`）。

- メッシュは 1 つで、レイヤーごとにプリミティブを 1 つ持つ。プリミティブの並びが重ねる順。
- 座標は Y が上、単位はメートル。メッシュは XZ 平面（Y = 0）に置き、法線は +Y。
  メッシュグラフの三角形（X を右・Z を上に見て反時計回り）は、Y が上の右手系では裏を向くので、
  書くときに向きを入れ替える。真上から見ると X が右、Z が下で、テクスチャは裏返らずに見える。
- テクスチャは `.glb` の中に埋め込む（Albedo、Normal、ORM）。同じものを画像ファイルとしても横に書く
  （エンジンへ別々に取り込むため。Roughness などの単体のマップと、Displacement の EXR も出る）。
- Roughness / Metalness / AO のどれも繋がっていないマテリアルは、ORM を持たず、係数（Roughness 0.5、Metalness 0）で書く。
- プリミティブの `extras.name` に、メッシュ出力の名前を入れる。
- 頂点の属性は `POSITION` / `NORMAL` / `TANGENT` / `TEXCOORD_0` / `COLOR_0`（アルファに頂点の `alpha`）。
  角ピースを回して貼るので、`TANGENT` を書いて法線の向きを確定させる。
- マテリアルは `alphaMode: BLEND`。テクスチャは Albedo（アルファに Opacity）、Normal、ORM。
  glTF の法線は OpenGL の向きなので、Material Output が DirectX なら緑を反転して書く。
- サンプラは Repeat。塗りの UV は 0〜1 を超える。
- 下地は書き出さない。
- glTF 用のライブラリは足さず、いまある JSON のライブラリで書く。

## CLI

```
surfgraph-cli asset <project> --out <dir> [--res N]
```

実装済み。使い方は [cli.md](../reference/cli.md)。

- `<dir>/<名前>.glb` とテクスチャ一式を書く。
- `<dir>/preview.png` に、真上から見たアセット（下地つき）を描く。Claude Code が目で確かめるための画像。
- `<dir>/uv.png` に、区画の確認用の絵を貼った表示を描く。区画ごとに色が違い、u が増える向きへ明るくなり、
  v = 0 の側（帯の外側）に白い帯が出るので、どのピースがどの区画へ、どの向きで割り付けられたかが分かる。
- メッシュグラフやマテリアルにエラーがあれば、メッセージを出して終了コード 1。
- 2 枚の絵は CPU のラスタライザ（`src/mesh/AssetRaster.cpp`）で描く。目で確かめるためのもので、
  3D ビューの代わりではない（Albedo に、法線から作った簡単な陰を掛けるだけ）。
  3D ビュー用の GPU のラスタライズは「実装の順番」の 4 で足す。

`render` / `check` / `golden` / `export` は、プロジェクトの中のマテリアルも指定できる
（`<project> --material <名前>`）。内包のマテリアルを単体で確かめるため。

2. **アセットの組み立てと書き出し**（UI なし）: プロジェクトファイル、UV の割り付け、`.glb`、CLI の `asset`。

   **実装済み**（3 より先に入れた。3 とは互いに依存しない）。マウス操作は人の手で未確認。
5. **パスの編集**: 真上からのビュー、頂点の編集。

1 〜 3 は CLI だけで確かめられる。手でプロジェクトファイルを書けば、エディタが無くても補修パッチを
