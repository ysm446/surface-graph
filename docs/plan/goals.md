# goals — プロジェクトの目的と完成形

作成日時: 2026-11-22 20:28
更新日時: 2026-11-25 16:21

仕様書: [surface-graph 仕様書](https://claude.ai/artifact/JbQm14E7aePXdUCXaoXpzK)

## 目的

ノイズとパターンを組み合わせて、ビットマップに頼らずタイル可能な PBR マテリアルを作る
ノードベースのエディタを作る。Substance Designer のワークフローを手本にする。

そのうえで、作ったマテリアルを帯や多角形のメッシュに割り当てて、**貼り物のアセット（メッシュデカール）**を
作れるようにする。道路の白線、アスファルトの補修パッチ、ひび割れ跡のような、方向性のある帯を使ったものを
想定する。アセットはメッシュとして書き出す。

- 言語: C++20
- グラフィックス API: DirectX 12（コンピュートシェーダー中心）
- シェーダ: HLSL (SM 6.6) / DXC
- UI: Dear ImGui（docking）+ imgui-node-editor
- 対象 OS: Windows のみ

UI の見た目と操作は、姉妹プロジェクト terrain-graph（`D:/GitHub/terrain-graph`）に合わせる。
`src/rhi` `src/core` `src/ui` は terrain-graph から移したもので、配色・部品・寸法を共有する。

## 完成形

1. **ゴール 1**: ノードグラフだけで、PBR テクスチャ一式（Albedo / Normal / Roughness / Metalness /
   AO / Displacement / Opacity）を生成できる。マップの名前と決まりは **Megascans に合わせる**
   （[docs/design/material-output.md](../design/material-output.md)）。
2. **ゴール 2**: パラメータを変えると、2048² のグラフが 100ms 以内に再評価され、3D プレビューに反映される。
3. **ゴール 3**: グラフを JSON で保存でき、同じシードなら同じ出力がビット単位で再現される。
4. **ゴール 4**: 複数のマテリアルを同時に扱い、パス（頂点の並び）から作った**塗り**（多角形）と
   **線**（帯）にそれぞれマテリアルを割り当てて、デカールのアセットを組み立てられる。
   下地のマテリアルの上に重ねて 3D ビューで確かめられる。
   - 補修パッチは「閉じたパス + 塗り + 線」、白線やひび割れは「開いたパス + 線」で作る。
   - 直角に折れる縁は、辺と角のピースをテクスチャの区画から UV で切り出して貼れる（9 スライスの発想）。
5. **ゴール 5**: アセットを、メッシュ（`.glb`）とテクスチャ一式として書き出し、エンジンで表示できる。

方針は [plan.md](plan.md) の「デカールアセットの方針」、設計は
[docs/design/decal-asset.md](../design/decal-asset.md)。

## 重視する価値（プロシージャル設計の原則）

全ノードは「入力テクスチャ + パラメータ + シード → 出力テクスチャ」の純粋関数として実装する。

1. **解像度非依存**: 座標はすべて UV（0〜1）。半径や強度も UV 単位で持つ。
   512² で調整したグラフが 4096² でも同じ見た目になる。
2. **シームレス保証**: ノイズは周期境界（格子のハッシュを周期で折り返す）、サンプリングはすべて Wrap。
   スケールは整数にして周期を保つ。
   - 例外: 帯に貼るマテリアルは U 方向（帯の長さ方向）だけタイルし、V 方向の端は Opacity が 0 に落ちる。
     タイルするかどうかを軸ごとに持てるようにする。
3. **決定論的な乱数**: グローバルシード + ノードごとのシードをハッシュで混ぜる。
   GPU ではステートレスなハッシュ（pcg3d）だけを使う。
4. **パラメータの公開**: ノードの任意のパラメータをグラフ入力として公開できる。
5. **グレースケール優先**: 中間データの大半は高さ・マスクなので R16F が標準。色は最後に Gradient Map で付ける。
   「形 → 高さ → 材質 → 色」という制作の流れに対応する。
6. **マテリアルグラフの形式は 1 つ**: `.sgraph` は 1 つのマテリアルのまま変えない。デカールのアセットは
   別のプロジェクトファイルとして持ち、マテリアルグラフは内包しても、外部の `.sgraph` を参照してもよい。
   どちらも中身は同じ形式にする。保存形式、CLI、基準画像のテストをそのまま保つため。

加えて、**Claude Code が自分で検証できること**を重視する。UI より先にヘッドレス CLI を作り、
ノードを足すたびに画像へ書き出して確かめる（[plan.md](plan.md) の「検証パイプライン」）。

## 当面の非目標（v1）

- メッシュベイク（ハイポリからのノーマル / AO ベイク）。
- ビットマップのスキャン補正。
- Substance 形式（.sbs / .sbsar）との互換性。
- Windows / DirectX 12 以外のプラットフォームおよび API への対応。
- デカール以外のメッシュの編集（立体の形状、穴のあいた多角形）。
- 配置や地形への投影。アセットは平らなメッシュとして書き出し、置くのはエンジン側で行う。
- 中央もセルに切って 1 マテリアルにまとめる方式、複数のデカールのアトラス化。あとから足せる形にしておく。
