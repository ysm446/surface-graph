## 全体の構成

UI はグラフモデルを編集するだけで、GPU を直接触らない。評価エンジンが変更のあったノードだけを
再計算し、結果のテクスチャを UI に返す。評価エンジンは UI に依存しないので、同じコードを
ヘッドレス CLI から使える。

| 層 | 場所 | 役割 |
| --- | --- | --- |
| UI | `src/app` `src/ui` | ノードエディタ、パラメータ、2D ビュー、アンドゥ |
| グラフモデル | `src/graph` `src/io` | Graph / Node / Link / Param、ノードのレジストリ、JSON |
| 評価エンジン | `src/engine` | 評価順、ハッシュによる再計算の判定、テクスチャプール、3D ビューの描画 |
| DX12 ラッパー | `src/rhi` | デバイス、ディスクリプタヒープ、シェーダコンパイル、PSO |
| CLI | `src/cli` | `surfgraph-cli`（render / check / golden / nodes） |
| プロジェクトとメッシュグラフ（予定） | 未定 | プロジェクトのグラフ、メッシュグラフのノードと CPU での評価（GPU も UI も使わない） |

設計の詳細は [docs/design/architecture.md](../design/architecture.md)。

## ロードマップ

フェーズごとに関門を置き、これを満たすまで次に進まない。日程は未定。

| フェーズ | 内容 | 関門 |
| --- | --- | --- |
| 1. 基盤 | DX12 ラッパー、グラフモデル・JSON、評価エンジン、ヘッドレス CLI、Perlin → Levels → Output | CLI で PNG 出力 |
| 2. エディタ | ImGui Docking、ノードエディタ、パラメータ・2D ビュー、Undo / Redo、サムネイル | GUI で編集 → 保存 |
| 3. PBR 一式 | 優先度 A のノード、Height → Normal / AO、3D ビュー（GGX + IBL）、エクスポート | レンガを一から作れる → エンジンで表示 |
| 4. 表現力 | Flood Fill・Scatter、Slope Blur 強化、Subgraph、Pixel Processor、バッチ出力 | — |
| 5. プロジェクト | プロジェクトファイルとプロジェクトのグラフ、マテリアルノードから中に入る操作、グラフごとの評価、編集していないグラフの中間テクスチャの解放、軸ごとのタイル設定 | 2 つのマテリアルを置いて、中に入って編集 → 保存 → 開き直す |
| 6. メッシュグラフと表示 | メッシュグラフ（パス、矩形、塗り、線、メッシュ出力）、ビュー上でのパスの編集、アセット出力、3D ビューのラスタライズ化、角ピース、下地の上への重ね表示 | 補修パッチ（塗り + 線）と白線を 3D ビューで表示 |
| 7. アセットの書き出し | `.glb` とテクスチャ一式 | 補修パッチをエンジンで表示 |

UI より先に CLI を作るのが要点。フェーズ 1 の時点で Claude Code が自分で出力を確かめられるので、
以降のノード追加を大きく任せられる。

フェーズ 4 と、フェーズ 5 以降は独立している。フェーズ 3 の関門を通したあとは、フェーズ 5 以降を先に進める。

## デカールアセットの方針

貼り物のアセット（[goals.md](goals.md) のゴール 4 / 5）の設計方針。実装に入るときに `docs/design/` へ
設計として書き起こす。

### 構成: 3 種類のグラフ

形状もプロシージャルに作る。グラフを 3 種類に分け、プロジェクトのグラフから中に入って編集する。

| グラフ | 中身 | 評価 | 保存 |
| --- | --- | --- | --- |
| プロジェクト | マテリアルノード、メッシュノード、1 つのアセット出力を繋ぐ | — | プロジェクトファイル |
| マテリアル | いまのノードグラフ（テクスチャを作る） | GPU | `.sgraph`（プロジェクトから参照する） |
| メッシュ | パスからメッシュを作る | CPU | プロジェクトファイルに埋め込む |

- マテリアルノードをダブルクリックすると、マテリアルグラフに入る（いまのアプリの画面）。
- メッシュノードをダブルクリックすると、メッシュグラフの編集画面に入る。
- 中に入る仕組みは、フェーズ 4 の Subgraph と共通にする。
- `.sgraph` は 1 マテリアルのまま変えない。未保存の状態とアンドゥの履歴は、ファイルごとに持つ。

### プロジェクトのグラフ

```
メッシュ ──▶ マテリアル ──▶ アセット出力（入力の並び = 重ねる順）
```

| ノード | 内容 |
| --- | --- |
| マテリアル | `.sgraph` を 1 つ参照する。メッシュを繋ぐと、そのメッシュにマテリアルが適用される |
| メッシュ | メッシュグラフを 1 つ持つ。メッシュグラフの出力ノードが、そのまま出力ピンになる |
| アセット出力 | マテリアルの付いたメッシュを集めて 1 つのアセットにする。入力の並びが重ねる順になる。プロジェクトに 1 つだけ置く |

- **1 プロジェクト 1 アセット。** アセット出力は 1 つで、マテリアルグラフの Material Output と同じ位置づけ。
- マテリアルの割り当てはメッシュごとに決める。メッシュノードの出力ピン（メッシュグラフのメッシュ出力）を
  1 つずつマテリアルノードへ繋ぐ。補修パッチなら、中央と縁の 2 つのピンを別々のマテリアルへ繋ぐ。
- 下地（重ねて見るための参照用のマテリアル）は、プロジェクトに 1 つ指定する。書き出しには含めない。

### メッシュグラフ

グラフのモデル、JSON、エディタはマテリアルグラフと共用する。ノードのレジストリと評価は別に持つ。
ピンの型はパスとメッシュで、評価は CPU で行う。再計算の判定はマテリアルグラフと同じくハッシュで行う。

最初に作るノードは 5 つ。

| ノード | 入力 → 出力 | 内容 |
| --- | --- | --- |
| パス | → パス | 頂点の並び。開いているか閉じているかを持つ。頂点はビュー上で編集する |
| 矩形 | → パス | 幅と高さから閉じたパスを作る |
| 塗り（Fill） | パス → メッシュ | 閉じたパスの内側を三角形分割する（凹多角形は耳刈り法）。UV はワールド座標の平面投影 |
| 線（Stroke） | パス → メッシュ | パスに沿った帯。幅と、内側 / 中央 / 外側の寄せ、角の処理を持つ。U は弧長 |
| メッシュ出力 | メッシュ → | 名前を持つ。1 つのメッシュグラフに複数置ける |

- 補修パッチは、1 つのメッシュグラフの中で、同じパスを塗りと線の両方へ繋ぎ、メッシュ出力を 2 つ置く。
  中央は両方向にタイルする普通のマテリアルで、多角形の切り口は縁の帯が上から隠す。
  縁と中央は同じパスから作るので食い違わない。
- 白線やひび割れは「開いたパス → 線」。
- パスを自動で作るノード（シードからひび割れの経路を作る、など）はあとから足す。
  シードを変えるだけで形の違うアセットを作れるようにする。
- 手動のパスのために、頂点列というパラメータの型と、ビュー上の編集操作が新しく要る。
- 穴のあいた多角形は扱わない。

### 帯のマテリアル

- U 方向だけタイルし、V 方向の端は Opacity が 0 に落ちる。タイルするかどうかを軸ごとに持つ。
  Blur や Warp が反対側の端から回り込まないよう、タイルしない軸は Clamp でサンプリングする。
- 閉じた帯は、一周でタイルが整数回になるように、周長に合わせて U を伸縮させる。
- 横長の出力（2048×256 など）をそのまま使う。

### 角の処理

線の角の処理は 3 つから選ぶ。

| 処理 | 内容 |
| --- | --- |
| 留め継ぎ | 角で帯を斜めに突き合わせる |
| 丸め | 角を分割して丸める |
| 角ピース | 辺と角を別のピースにして、テクスチャの区画から UV で切り出して貼る。90° の角だけ |

角ピースは 9 スライス（CSS の `border-image`）と同じ発想で、「凸」の字のような直角に折れる形に使う。

- 最小の構成は、辺（幅 × 任意の長さ、U 方向だけタイル）、外角（幅 × 幅）、内角（幅 × 幅）の 3 種類。
  回転して 4 方向に使い回す（反転はしない。接線の向きが変わるため）。
- 辺の長さは、タイルが整数回になるように辺ごとに伸縮させる。
- 区画の間には余白を取る（ミップマップのにじみを避ける）。辺は横幅いっぱいの段にして、U 方向は Wrap のまま使う。
- パスの編集に、グリッドへのスナップと直角の拘束を入れる。
- **UV はマテリアルを繋いだ時点で確定させる。** メッシュには「ピースの種類（辺 / 外角 / 内角）と、
  ピース内の UV」だけを持たせ、マテリアルに繋いだときにテクスチャの区画へ割り付ける。
  マテリアルを差し替えても、メッシュグラフを直さずに済む。
  マテリアル側には、区画の配置を宣言する設定を持たせる。

### 継ぎ目: 重ねてブレンドする

角と辺の継ぎ目は、絵を一致させるのではなく、メッシュを重ねてブレンドして消す。

- 角のピースを辺の方向へ少し延ばし、辺の上に重ねる。
- **フェードさせるのは上側（角）だけ。** 下の辺はそのまま通す。両方を逆向きにフェードさせると、
  重なりの中央で不透明度が落ちて下地が透ける。
- 縁の V 端の半透明の部分は、重なった区間だけ少し濃くなる。目立つかどうかは描いて確かめる。
- 開いたパスの始端と終端も同じ仕組みで作る（端のピースを中間の帯に重ねる）。

### ドローコール

- 中央（塗り）で 1 回、縁（辺 + 角）で 1 回の、合わせて 2 回。
- 角と辺は同じマテリアルなので 1 つのメッシュに入れ、インデックスの並びを「辺が先、角が後」にする。
  同じドローコールの中では、三角形はインデックスの順に描かれる。
- 深度を書き込まないマテリアルを前提にする。
- 中央と縁は同じ平面で重なる。重ねる順はアセット出力の入力の並びで決め、
  書き出しでそれをどう表すかはエンジンに合わせる（下の「未決定」）。

### 未決定

| 項目 | 案 |
| --- | --- |
| 持っていく先のエンジン | 未定。重なりの順序の扱いと、頂点アルファの使い方がこれで決まる |
| 重なりのフェードの付け方 | 頂点アルファ（重なりの長さをメッシュのパラメータにできる）。テクスチャの Opacity に描く方式もある |
| 重ねる順の書き出し方 | レイヤーごとに微小な高さのずらしを入れるか、エンジンのソート優先度に任せる |
| エンジンが三角形の順序を並べ替える場合 | 角だけ微小に高くするか、角を 3 つ目のドローコールに分ける |
| プロジェクトファイルの拡張子と形式 | 未定（中身は JSON） |
| プロジェクトとメッシュグラフのコードを置く場所 | 未定（`sg_graph` と同じく GPU も UI も使わないライブラリにする） |
| マテリアル側の区画の配置の宣言 | 未定（グラフ設定に持たせる案） |
| パスを編集するビュー | 未定（3D ビューの上で編集するか、専用の 2D ビューを作るか） |

## 検証パイプライン

```
surfgraph-cli render graphs/tests/all_nodes.sgraph --out data/out/all --res 1024
  → data/out/all/<nodeId>_<type>.png を全ノード分、contact_sheet.png に一覧
```

- **ゴールデンテスト**: ノードごとに基準画像（`graphs/tests/golden/`）を持ち、PSNR と最大誤差が
  閾値を超えたら失敗にする。
- **シームレステスト**: 出力の左右端・上下端の差を数値で自動チェックする。
- **解像度非依存テスト**: 半分の解像度で評価したものと、縮小したものを比べる。
- **決定論テスト**: 同じシードで 2 回評価してビット一致を確かめる。

すべて `ctest --test-dir build -C Debug` で走る。使い方は [docs/reference/cli.md](../reference/cli.md)。

デカールアセットで足す検証（予定）:

- **タイルしない軸の検査**: シームレステストを軸ごとにし、タイルしない軸では端の Opacity が 0 であることを確かめる。
- **メッシュグラフの単体テスト**: 評価は CPU だけなので、三角形分割、帯、角ピース、UV を単体テストで確かめる。
  同じシードで 2 回評価して、頂点とインデックスが一致することも確かめる。
- **角と辺の断面の差**: 重ねてブレンドするので必須ではないが、差が大きいとぼやけるので目安として出す。
- **CLI でのアセットの描画と書き出し**: 画像と `.glb` を CLI から出せるようにする。

## 当面の優先順位

1. **フェーズ 2 の関門を人の手で確かめる**（GUI で編集 → 保存 → 開き直す）。
   マウス操作は自動では確かめられていない（[progress.md](progress.md) の「未確認」）。
2. フェーズ 2 の残り: リンク上へのドロップで挿入、コメント枠とグループ、ヒストグラム、
   ピクセル値のホバー表示、ノードごとの GPU 時間（プロファイラ）、サムネイルのミップ生成。
3. フェーズ 3: エクスポート（PNG 16bit / EXR / DDS、パッキングのプリセット。Megascans の `_ORD` を含む）、
   3D ビューの HDRI による IBL、Bitmap Input、Curve。
   3D ビューの最初の版（球 / 平面、GGX、手続きの空、パララックス）は実装済み。
4. フェーズ 5 〜 7: デカールアセット。フェーズ 3 の関門を通してから始める。
   - VRAM の上限を超えたときの LRU 解放（フェーズ 2 の残り）は、複数マテリアルの前提になる。
   - 3D ビューのラスタライズ化は、フェーズ 3 の残り（OBJ、テッセレーションによる変位）と共通の土台になる。
5. フェーズ 4: Flood Fill、Subgraph、Pixel Processor、バッチ出力。
   Subgraph は、グラフの中に入る仕組み（フェーズ 5）と基盤を共有する。

## タスクの分担

| Claude Code に任せやすい | 人間が見るべき |
| --- | --- |
| ノードの追加（定義 + HLSL + テストグラフ） | 質感の良し悪し、パラメータの手触り |
| JSON の保存・読込、Undo、コマンド類 | GPU のハングやバリアの不具合（PIX / RenderDoc のキャプチャを渡す） |
| シェーダーの数学（ノイズ、GGX、JFA） | UI の操作感、ノード配置の使いやすさ |
| エクスポート、パッキングプリセット | エンジンに取り込んだときの見た目 |
| メッシュグラフのノード（三角形分割、帯、角ピース、UV）、`.glb` | パスの編集の操作感、グラフの中に入る操作の分かりやすさ、重なりのブレンドの見た目、エンジンでの重なりの順序 |
