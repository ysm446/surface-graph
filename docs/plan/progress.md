### デカールアセット — パスの編集と曲線（2026-11-25）

[decal-asset.md](../design/decal-asset.md) の「実装の順番」の 5。考え方と操作は road-material-editor の Path を手本にした。

- **パスの曲線**（`src/mesh/PathCurve.cpp`）: パスノードに「曲線」（直線 / 2 次ベジェ / 3 次 B スプライン / クロソイド）、
  「丸め」「クロソイドの割合」「分割数」を足した。置いた頂点は制御点で、曲線は折れ線の内側を回る。
  閉じたパスは全部の角を丸める。既定は直線なので、これまでのファイルは同じ結果になる。
- **帯ノード**（当時の名前は「線」）: 角や端のピースのぶんを、道のりで削るようにした（曲線の端でも端のピースが付く）。
  緩い折れには、留め継ぎ用の余分な断面を足さない。
- **真上からのビューでの編集**: 頂点を選ぶ・動かす（格子と、隣の頂点の X / Z に吸着）、Ctrl + クリックで足す・挿入する・
  閉じる、Delete と右クリックのメニューで消す・反転する。Ctrl を押している間は、次に起きることを先に描く。
  縮尺は、頂点を動かしている間は変えない。
- サンプルのひび割れのシールを、クロソイドの曲線にした。
- 単体テスト（曲線の形、端点、滑らかさ、決定論、線との組み合わせ、保存と古いファイルの読み込み）と、確認用の絵
  （`data/out/mesh/curve_patch.png`、`curve_kinds.png`）。編集画面はスクリーンショットで表示だけを確かめた。

### デカールアセット — 3D ビューでの編集と UV の表示（2026-11-25）

- **3D ビューでパスを編集できる**: 頂点を地面の上の点として掴む。操作は真上からのビューと同じ（共用のコード）。
  頂点を掴んでいる間と Ctrl を押している間は視点を動かさない。「真上」のボタンで、真上から見る向きにできる。
- **表示中の出力を 3D ビューに出す**: メッシュグラフで出力ピンをクリックしたノードの結果を、メッシュ出力や
  マテリアルに繋いでいなくても、区画の確認用の絵でアセットの上に重ねる。パスは琥珀の細い帯で出す。
- **2D ビューは UV**: プロジェクトとメッシュの階層の 2D ビューを、UV の表示（テクスチャの上にメッシュの UV、区画の枠）
  にした。「真上」に切り替えると、これまでの真上からの図になる。
- 3D ビューの描く範囲は、エディタが決めて渡す（頂点を動かしている間は変えない）。
- スクリーンショットで、3D での編集の表示、線の UV、繋いでいない出力の 3D と UV を確かめた。マウス操作は未確認。

### デカールアセット — 複数選択と移動ギズモ（2026-11-25）

- **矩形での選択**: 空をドラッグして、パスの頂点をまとめて選ぶ（Shift で足す。Shift + クリックでも足す / 外す）。
- **まとめて動かす**: 選んだ頂点のどれかを掴んで動かすと、全部が同じだけ動く。
- **移動ギズモ**: 選んだ頂点の重心に、X と Z の矢印と、平面の四角。軸に沿って動かせる。Y は出さない（メッシュは平ら）。
- **3D ビューの視点**: DCC ツールに合わせ、Alt + 左 / 中 / 右ドラッグで回す / パン / 近づく・離れる。
  メッシュグラフの中では、Alt なしの左ボタンは編集に使う。
- スクリーンショットで、ギズモの表示（頂点 1 つ、全部を選んだとき）を確かめた。マウス操作は未確認。
- **マージのノード**（`mesh.merge`）: メッシュを 4 つまで 1 つにまとめる。塗りと帯を 1 つの出力にできる。
- **3D ビューのワイヤーフレーム**: 「表示設定 > ワイヤーフレーム」で、メッシュの上に三角形の辺を黒い線で重ねる。
- **3D ビューの視点を、地面の下へも回せる**ようにした。下からは地面を描かず、裏面が見える。

  ノードの追加、レイヤーの並べ替え、アンドゥ、保存して開き直す、アセットの書き出し）。ビルドと起動、
  `--screenshot-ui` での各階層の表示までは確認した。
- **`.glb` を外のツールで開くこと**。構造は自前の検査で確かめたが、Khronos の glTF Validator と、
  ビューア（Blender など）やエンジンでの読み込みは確かめていない。重ねる順（プリミティブの並び）と
  頂点の `alpha` がどう扱われるかは、持っていく先で変わる。
- **3D ビューのマウス操作**（視点とライトのドラッグ、ホイール、表示設定のポップアップ）。
  球と平面の表示はスクリーンショットで確認した。
- **Megascans の法線の向き**。公式資料で確認できておらず、既定を DirectX にしてある
  （[material-output.md](../design/material-output.md)）。実際の素材と並べて確かめたい。

## 注意点

- **仕様書からの変更点**は [docs/design/architecture.md](../design/architecture.md) の「仕様書との違い」に
  理由付きでまとめてある。主なもの:
  - パラメータの定数バッファは `SG_PARAMS { ... }` をシェーダに書くのではなく、定義から作った宣言を
    `-D SG_PARAMS_DECL=...` で注入する（シェーダ側はパラメータ名をそのまま使う）。
  - dirty フラグの伝播ではなく、ノードの内容のハッシュで再計算を判定する。
  - Undo はコマンドパターンではなく、グラフ全体のスナップショット。
  - 色は表示色（sRGB の値）のまま持ち、合成も表示色の空間で行う（Substance Designer と同じ）。
  - グラフの拡張子は `.sgraph`（中身は JSON）。
- **Distance の精度**: 中間テクスチャが RGBA16F なので、4096² では最も近い点の位置が 1 ピクセルほどずれる。
- **解像度非依存の例外**: Edge Detect と Curvature のような細い線を出すノードは、線の太さがピクセルに
  引きずられる。check の閾値はこのぶん余裕を持たせている（0.06）。
- **Tile Generator**: 行数が奇数で「ずらし」を使うと、上下の繋ぎ目で 1 行おきのずれが崩れる。
- シェーダのキャッシュは `%LOCALAPPDATA%/surface-graph/shader-cache`（エディタのみ。CLI は毎回コンパイルする）。
- **テストはリポジトリに入れていない。** `tests/`（単体テスト）と `graphs/tests/`（テスト用グラフと基準画像）は
  `.gitignore` で外してあり、手元にあるときだけ CMake が組み込む。クローンし直した環境では `ctest` は 0 件になる。
  テスト用グラフは `python tools/make_test_graphs.py` で作り直せる（基準画像は `golden --update` で作る）。
- `data/` は `.gitignore` で外してある。CLI の出力とスクリーンショットの置き場に使う。
- リポジトリは `git init` しただけで、まだ 1 度もコミットしていない。
